# Space Defenders: 0.9 polish review

This iteration preserves the dual-station arcade game and authored artwork, while removing startup friction and making its controls and combat feedback more predictable. It is a desktop playtest candidate; it still needs real-camera and cross-browser playtesting before being called production ready.

## Design direction

Use quiet dark panels with one obvious primary action. Blue identifies Pilot, cyan identifies Gunner controls in the menu, and orange/red communicates heat or danger. Retain the original logo and sprites. Keep instructions adjacent to the launch action and visible again during pause. Show warning text steadily instead of blinking away the information a player needs.

The menu adapts to small screens and zoom. Gameplay retains its 1280×720 dual-view canvas; touch controls and a fully responsive combat HUD are a separate iteration. The desktop requirement is stated before launch.

## Loading and performance

- Original image files: 8,249,693 bytes; optimized files: 5,349,500 bytes. This saves transfer bytes, not decoded texture memory, because dimensions are intentionally unchanged.
- The approximately 7.46 MiB hand model and one approximately 10–11 MiB WASM variant load only after camera permission is granted.
- MediaPipe JavaScript is split into an on-demand chunk. Phaser remains the dominant initial bundle; the production build still reports its large-chunk advisory.
- The camera requests 640×480 frames at up to 30 FPS; inference ignores duplicate video frames and hidden tabs. The debug camera overlay is off by default.
- Inference still runs synchronously on the main thread. A worker-based pipeline needs profiling on lower-end hardware before implementation.
- Asset and model URLs use Vite's BASE_URL, enabling builds under a repository subpath.

## Next playtest priorities

1. **Physical camera testing:** verify left/right role mapping, thumb flick recognition, lighting tolerance, GPU and CPU delegates, permission recovery, and reconnect behavior. Automated lifecycle tests cannot establish gesture quality.
2. **Balance and difficulty:** play complete runs at 30/60/120 Hz. Confirm the six-second cannon and shield absorption/recharge feel fair against meteors, beams, missiles, and boss attacks. Introduce a gentle first-wave ramp if onboarding remains difficult.
3. **Collision/art audit:** most sprites contain substantial transparent margins. Draw temporary hitbox overlays and align collision shapes with artwork; normalize animation pivots before cropping or resizing. This pass only adjusts the known beam mismatch.
4. **HUD consolidation:** preserve both stations' identity while making hull, pilot shield, gunner defenses/lives, heat and targeting visually consistent. Confirm readability at 1366×768 and 200% zoom.
5. **Audio and accessibility:** add intentional firing/lock/impact cues, then a working mute control; provide reduced shake settings and evaluate color-independent threat cues. Add touch play only with a coherent control layout.
6. **Long-session profiling:** measure FPS, inference latency, object counts and memory during real twenty-minute runs on integrated graphics; use atlases/object pools or worker inference where measurements justify them.

## Verification

Run `npm test`, `npm run check`, and `npm run build`. Chromium automation verified keyboard launch, movement, shield damage absorption, cannon overheat/cooling, pause/resume, defeat/retry, camera failure fallback, responsive menu scrolling, and twenty mission cycles. FIRE and GET_HULL listener counts remained one each; star counts remained 50/100; no browser errors occurred in that gameplay run. A separate recovery run verified an intentionally failed cannon asset, successful retry, focus-loss pause, credits navigation, and scrolling in a 1280×360 viewport. A production build under /SPACE-DEFENDERS-21st-Century/ launched and paused successfully with no missing assets or model requests. Screenshots are retained locally under output/playwright. See the README for the playtest steps. Production acceptance also requires the physical-camera, cross-browser and long-session checks above.
